## Executive summary

The video demonstrates an agentic research loop: Claude Code does the source discovery, setup, and local note generation, while NotebookLM does large-source grounding and citation retrieval. The practical point is not that Claude magically gets a bigger context window. It is that Claude delegates a curated corpus to NotebookLM, asks questions against that corpus, receives cited answers, and writes those answers/citation maps back into an Obsidian vault where they can be browsed, linked, audited, and reused.

The underlying tool is `notebooklm-py`, an unofficial Python/CLI wrapper around Google NotebookLM. It exposes NotebookLM operations to agents: create/list notebooks, add URLs/YouTube/PDF/files, ask questions, set chat persona, generate audio/video/quiz/flashcards/mind maps/slide decks/data tables, and download artifacts. The big caveat is that it relies on undocumented Google NotebookLM APIs and Google login cookies, so it is best treated as a personal/research automation layer rather than stable production infrastructure.

## What the video’s workflow actually does

1. **Start from a research objective inside Claude Code / Obsidian.**
   - Demo topic: Claude Code + Obsidian integration.
   - Claude Code is run from inside the user’s Obsidian vault so outputs can be written directly as Markdown notes.

2. **Load a NotebookLM skill / CLI instructions.**
   - Claude is taught how to use the NotebookLM command-line interface.
   - The project referenced near the end is `notebooklm-py`, which ships a NotebookLM skill and CLI.

3. **Discover candidate sources.**
   - Claude uses a YouTube-search skill to find relevant videos.
   - It ranks/selects roughly 20 videos for relevance and diversity instead of relying on a generic deep-research black box.
   - Later examples add web articles plus existing vault Markdown notes.

4. **Create a new NotebookLM notebook.**
   - Claude creates a notebook such as “Claude Code Obsidian Research.”
   - It adds selected YouTube URLs as NotebookLM sources, reportedly in parallel batches.
   - NotebookLM handles the heavy source processing and transcript chunking.

5. **Ask cross-source research questions from the terminal.**
   - Example prompt: identify emerging themes, gaps, and opportunities across the imported videos.
   - Claude sends the question to NotebookLM through the CLI.
   - NotebookLM returns grounded answers with citations to specific source chunks.

6. **Bring the answers back into Obsidian.**
   - Claude writes the NotebookLM answer into the vault as Markdown.
   - It creates a Q&A log containing question, answer, citations, source references, and metadata/YAML.
   - The demo emphasizes a `--json` style output path for citation resolution, so references can be imported instead of pasted as loose text.

7. **Resolve citations into clickable vault links.**
   - NotebookLM citations point to source chunks/passages.
   - Claude maps those citations into Obsidian wiki links and headers so the user can click from a claim to the relevant source note/passage.
   - The user can audit whether a citation is a strong, partial, or weak match.

8. **Build an Obsidian dashboard.**
   - Claude creates a dashboard showing all sources, summaries, topics, status, citation frequency, and Q&A logs.
   - Obsidian Bases/DataView/Markdown tables are used as possible display mechanisms.
   - The demo notes that Obsidian Bases may not always return data as expected, so DataView-style translation is a fallback.

9. **Use graph view for source/topic exploration.**
   - Each source becomes a file/node.
   - Extracted topics become links/tags, allowing the graph to show which sources mention the same concepts.
   - The example colors NotebookLM source nodes differently from topic nodes, making cross-source patterns visible.

10. **Generate NotebookLM artifacts and import them back.**
    - Audio Overview: Claude asks NotebookLM to generate a podcast-style overview focused on research gaps, downloads it, and embeds the MP3 in Obsidian. Obsidian Sync makes it listenable on mobile.
    - Mind maps: generated by NotebookLM, then imported/exported for local use.
    - Flashcards: generated and imported as study cards.
    - Slide decks: possible, though the presenter is less impressed because they are less editable/useful.

11. **Extend the same loop beyond YouTube.**
    - Sources can include PDFs, papers, blog posts, company docs, podcast episodes, personal daily notes, and existing vault notes.
    - The presenter highlights NotebookLM’s support for up to ~300 sources and gives an example of uploading 300 daily notes.

## Implementation-specific setup from `notebooklm-py`

Quick agent/CLI setup described by the project docs:

```bash
pip install "notebooklm-py[browser]"
playwright install chromium
notebooklm login
notebooklm auth check --test --json
```

Agent skill install options:

```bash
notebooklm skill install
# or
npx skills add teng-lin/notebooklm-py
```

Basic CLI loop:

```bash
notebooklm create "Claude Code Obsidian Research"
notebooklm use <notebook_id>
notebooklm source add "https://www.youtube.com/watch?v=..."
notebooklm source add "./paper.pdf"
notebooklm ask "What are the emerging themes and gaps across these sources?" --json
notebooklm generate audio "Deep-dive on the gaps and opportunities" --wait
notebooklm download audio ./notebooklm-gap-review.mp3
```

Useful project capabilities:

- Create, list, rename, and delete notebooks.
- Add sources from URLs, YouTube, files, Google Drive, pasted text, and research agents.
- Ask questions and retrieve references/citations.
- Set a custom NotebookLM persona (e.g. concise, no filler, no preamble).
- Generate and download audio overviews, video overviews, slide decks, quizzes, flashcards, reports, data tables, infographics, and mind maps.
- Use explicit notebook IDs/profiles for parallel agent workflows to avoid shared `notebooklm use` context collisions.

## Why it matters

- **Context-window workaround with source grounding:** Claude does not need to read all 300 files directly. It orchestrates source selection and asks NotebookLM to reason over the corpus.
- **Citation-first research:** The output is more auditable than a normal agent summary because NotebookLM returns claim-level citations.
- **Better source hygiene:** The user/agent can curate sources intentionally instead of trusting a black-box “deep research” corpus.
- **Reusable local knowledge:** Answers, citations, source summaries, topics, and generated artifacts become files in the user’s vault rather than one-off browser state.
- **Mobile/on-the-go consumption:** Audio overview exports become personalized podcasts synced through Obsidian.

## Critique / caveats

- **Unofficial API risk:** `notebooklm-py` uses undocumented Google NotebookLM RPCs/cookies. Google can break the integration at any time.
- **Auth/privacy risk:** The workflow requires Google/NotebookLM authentication and may upload private vault notes, PDFs, or company docs to Google’s service. Sensitive/legal/client material needs a governance decision first.
- **Citation quality is not perfect:** The demo’s own audit reports roughly 60% strong matches, ~31% partial matches, and ~10–15% weak matches. This is useful, but not enough for legal/academic publication without manual verification.
- **Source import does not equal understanding:** NotebookLM citations can still be shallow, wrong, or overfit to transcript chunks. The agent should audit important claims.
- **Obsidian graph usefulness depends on disciplined metadata:** If topics/tags are noisy, the graph becomes decorative. The value comes from good source files, consistent YAML, and reliable citation mapping.
- **Parallel agent hazard:** CLI context commands like `notebooklm use` can collide if multiple agents share a NotebookLM profile; automation should pass explicit notebook IDs or isolate profiles.

## Recommended adapted workflow for ai-update / Ed

1. Treat this as a **research-ingestion pattern**, not an immediate default for private/confidential material.
2. Use it first for public sources: X posts, YouTube videos, docs, public PDFs, product pages.
3. Keep every logged item with: original URL, extracted materials, transcript path, implementation steps, critique, and confidence level.
4. If NotebookLM is introduced here, use a dedicated Google account/profile and avoid syncing personal/private vault notes until privacy boundaries are explicit.
5. For each generated answer, require a citation audit step: sample citations, mark strong/partial/weak, and do not publish unsupported claims as facts.
6. For the ai-update site, this is worth a follow-up experiment: build a local “source pack → NotebookLM → cited review → ai-update entry” pipeline, but only after confirming the account/privacy setup.
